# SSH, firewall switch and login shell isolation, 2026-11-07

- **SSH lives in `server.json`.** `settings.ssh` holds the sign-in policy, the login alarm switch and the shell jail. An unset block means the policy the host has always rendered: keys only, root by key. Whole-settings writers cannot drop it, and `PUT /api/server/settings` refuses an SSH port change.
- **Nothing locks the operator out.** A policy that leaves no way in is refused before anything is saved: root needs a key or a usable password, or another sudo or wheel member must exist. Facts that cannot be read count as absent. Both methods off is `NO_AUTH_METHOD`.
- **A port moves in three steps.** The firewall opens the new port and sshd listens on both; the agent reads an SSH banner from the new port; only then does the old port close. A silent port restores everything. A failure in the last step leaves both ports open and says so. On EL the agent labels the port `ssh_port_t` first.
- **sshd is reloaded only when its drop-in changed**, so open sessions stay and a daemon the operator stopped stays stopped. A socket-activated sshd restarts its socket, which is the only way a new port listens. The reconciler used to write the drop-in without ever telling sshd.
- **Stop keeps the unit enabled**, so the daemon returns with the next boot. Start and stop are proved by the port, not by the exit code.
- **The login alarm reads the journal once a minute in the API**, with a cursor that starts at the present, and uses the alert outbox. A login notice is named after its journal entry, so a lost cursor write cannot send it twice. It ignores quiet hours; other alerts keep theirs.
- **Off is a real state.** The firewall renders `policy accept` and no operator rule. Bans, flood limits, the loopback-only backends and the database port stay guarded, because those belong to other controls. A first switch-on writes the default rules plus mail, DNS and FTP, which would otherwise go dark. The ping block is a base-chain drop, so it holds with the firewall on or off.
- **Login shells enter their view through one sudo rule.** systemd gives units a namespace; a login shell starts under sshd and holds no privilege to make one. `pam_namespace` needs `allow_polyinstantiation` on EL and an edit of `/etc/pam.d/sshd`, where a mistake locks everyone out. The sudo path fails closed for that account only, never for root. The entry script drops every privilege and sets no-new-privileges before the shell starts. With every switch off, no rule and no script exist. The rule ends in `""`, so sudo refuses any argument and root reads nothing the account chose: `SUDO_UID` picks the account, and `ssh host command` crosses on descriptor 3 (`closefrom=4`), which only the unprivileged jailshell reads after the drop. `ALL` stays as the user, because no group holds every account; the script refuses a UID outside 20000..60000.

Not built: an editable skeleton of allowed binaries; removing the SELinux label of an old SSH port; reading a provider firewall in front of the server.
