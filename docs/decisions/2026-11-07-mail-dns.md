# Mail and DNS extras: DNSSEC, mail client autoconfiguration, list administration, BoxTrapper (2026-11-07)

Owner decision 2026-11-06: build these as cPanel does (same user outcome and safety), adapted to this architecture
(desired state in files, the agent applies, PowerDNS with the BIND backend, Postfix and Dovecot with Pigeonhole).

## DNSSEC

**Where keys live.** PowerDNS signs answers live from keys in the BIND backend's own SQLite key store
(`bind-dnssec-db`); the zone files stay unsigned. cPanel with PowerDNS works the same way. The installer creates the
store at `/var/lib/powerdns/dnssec/bind-dnssec-db.sqlite3` (`pdns:pdns`, 0640) with `pdnsutil create-bind-db` and a
throwaway configuration, and names it in `pdns.conf` only when that succeeded; a PowerDNS build without SQLite support
keeps serving zones and DNSSEC reports `dnssec_key_store_unavailable`. A host installed before this change has no
store and reports the same reason; no host is edited by hand.

**Writer and observers.** `pdnsutil` (reviewed argv grammar, `packages/os/src/dnssec-command.ts`) is the only writer.
After every change the agent purges the zone's cached answers, reads the key store back (`list-keys`, `show-zone`) and
reads the local listener (`dig DNSKEY` and `dig SOA +dnssec`). DS records are computed from the published DNSKEY
(RFC 4034 key tag, RFC 4509 SHA-256 and SHA-384 digests), not copied from tool output; a test pins the RFC 4509 example.
The running server caches keys for up to 30 s and metadata for 60 s, so a change can read back as `pending`.
pdnsutil 4.5 (Ubuntu 22.04) through 4.9 take the legacy command names; pdnsutil 5.0 (EPEL 9 and 10) translates them.

**Choices against cPanel's list.** Algorithms follow RFC 8624: ECDSA P-256 (13, default), Ed25519 (15), ECDSA P-384
(14), RSA/SHA-256 and RSA/SHA-512 with 2048-bit keys; SHA-1 and DSA algorithms are not offered. NSEC3 uses zero extra
iterations and no salt (RFC 9276), with an opt-out switch, instead of free iteration and salt fields. Import and
export of private key material are not offered: key material never leaves the DNS server.

**Safety rules.** The last active signing key cannot be deactivated or removed (turn DNSSEC off instead), an active key
cannot be unpublished, a key is published before it is activated, turning DNSSEC off needs the zone name typed back.

**Rollover.** A ZSK rolls by pre-publication (RFC 6781 4.1.1.1): the new key is published inactive, then signing
switches, then the retired key is removed. A KSK or CSK rolls by double signature: the new key signs alongside the old
one, the owner gives its DS to the registrar and confirms, then the old key is removed. The start time and the earliest
finish (`DNSKEY TTL + 90 s`) are desired state in `extended/dns/dnssec/<zone>.json`; finishing earlier is refused
(`rollover_wait`). The parent's DS TTL is not observed, so the KSK step relies on the owner's confirmation.

**Reconcile.** A signed zone's AXFR carries DNSKEY, RRSIG and NSEC/NSEC3 records; the DNS observation leaves exactly
those types out so a signed zone still verifies against its zone file.

## Mail client autoconfiguration

cPanel answers Thunderbird autoconfig and Outlook autodiscover on `autoconfig.` and `autodiscover.` proxy names.
Here the nginx edge answers them for every account domain with at least one mailbox, from static `return 200` replies:
the Thunderbird document lists the rendered IMAP 993/143 and SMTP 465/587 listeners with `%EMAILADDRESS%` as the user
name, and the Outlook POX reply names the implicit-TLS IMAP and SMTP endpoints without a LoginName, so Outlook signs in
with the address typed. Static replies cost nothing per request (no daemon, no API call) on a 1 vCPU host and accept
Outlook's POST. Each site answers `/.well-known/autoconfig/mail/config-v1.1.xml` and `/autodiscover/autodiscover.xml`;
`autoconfig.<domain>` and `autodiscover.<domain>` get their own server blocks on port 80 and, where a certificate covers
the name, on 443. The zone template already publishes their A records and the `_autodiscover._tcp` SRV record.
A host whose server name is not a valid FQDN advertises nothing. Certificates do not yet request these names, so
HTTPS on the two names needs a certificate that covers them (a wildcard does).

## Mailing list administrator password and restart

cPanel keeps one Mailman administrator password per list: the account owner sets or changes it without the old one,
WHM "Reset a Mailman Password" replaces it, and the password signs in to the list's administration. This product has no
list manager daemon: lists are delivered from the Postfix alias table, moderation is described below, and archives stay
unavailable (Mailman 3 does not fit 1 vCPU / 1 GB and mlmmj ships very different versions across the five profiles).

- The password is kept as an Argon2id hash in `extended/mail/mailing-list-passwords.json`, apart from the list file
  every list reader parses; entries of deleted lists are dropped on the next write. The owner sets it from xPanel
  (`PUT /api/mail/mailing-lists/:id/password`), root resets it from WHM mailbox maintenance.
- Its consumer is list administration from xMail: a mailbox of the same account names the list address and its
  password on every call (`POST /api/webmail/mailing-lists/admin`), like a Mailman admin sign-in, to list, add and
  remove members. Member changes go through the mail routing reconcile like owner edits. Five wrong passwords lock that
  list's sign-in for 15 minutes; the lock is desired state, so it survives restarts.
- Restart Mailing List Manager restarts what delivers lists here: it runs the Postfix configuration test and restarts
  Postfix through the existing service restart. With no saved list it refuses with `no_mailing_lists`, matching
  cPanel's "the service only runs once a list exists".

## BoxTrapper

cPanel runs BoxTrapper as the account from an Exim router. Here delivery ends in Dovecot LMTP, which already acts as the
account, so the same place is a Sieve before-script.

**Delivery.** A mailbox with BoxTrapper on gets a second root-owned before-script (`sieve_before2`, after the spam policy
script) that calls the program through `vnd.dovecot.execute`. The extension is listed in `sieve_global_extensions`, so a
mailbox's own script cannot name it; `sievec` refuses it without that line (checked on Dovecot 2.3.16). The plugin lines
are rendered only while a mailbox has BoxTrapper on and the module file exists, so a mailbox without it pays nothing and a
host without the module keeps working Sieve. Without the module, saved settings stay inert and the page says why
(`sieve_extprograms_missing`).

**The program.** `apps/agent/src/boxtrapper-program.cjs`, installed by the reconciler in
`/usr/local/sbin/xpanel-sieve-execute`, a path the default SELinux policy is expected to label `bin_t`. It runs with
`node --jitless`, so the LMTP domain needs no executable memory. A bare `node --jitless` start measured 42 MB RSS and 32 ms
on the lab guest; the program itself was not timed, and it runs only for a mailbox with BoxTrapper on. It has no
dependencies, spools stdin to disk before it decides, and exits non-zero on any failure, which leaves the message in normal
delivery. A full queue day (5000 held messages) delivers too.

**State.** Settings and message templates are API state in `extended/webmail/boxtrapper/`, bound to the mailbox lifetime
like spam preferences, and reach the host as a rule file through the reconcile. The allow, ignore and deny lists, the
queue, the log and the notice limiter are files in `<maildir>/boxtrapper/`, owned by the account as cPanel's `.boxtrapper`
tree is, because the program writes them during delivery. Maildir++ ignores a directory without a leading dot, so they
travel with the mailbox through backups and moves and go with it on deletion. Root never opens these files: the agent runs
the same program through `runuser`, under a reviewed grammar, and the API re-validates each answer.

**Order.** Release mark, ignore, deny, verification reply, allow, score bypass, Sent folder, then hold. Ignore beats allow as
the catalog asks; deny beats allow because a block is the explicit choice. Automatic mail (null sender, `Auto-Submitted`,
`Precedence: bulk|list|junk`, `List-Id`, `List-Unsubscribe`, `mailer-daemon`, `postmaster`, `noreply`), mail the spam filter
flagged, mail not addressed to the mailbox and mail claiming to come from the mailbox are held without a reply. An automatic
reply never releases, even with the right token.

**Backscatter.** Notices go to the envelope sender with a null return path and `Auto-Submitted: auto-replied`. Each kind
reaches a sender once a day, with at most 100 notices per mailbox per day.

**Release.** The message re-enters through `sendmail`, so quota, the mailbox's filters and forwarders apply as to any mail.
A one-time mark on disk lets it past the filter once; its id is random and the mark is spent on use, so a sender cannot
forge it. The spam filter scans a released message again.

**Differences from cPanel.**
- Rules take `*` and `?` globs on `from`, `to` and `subject` instead of Perl regular expressions, matched without a
  backtracking engine, so a saved rule cannot stall delivery. A bare line is a sender pattern.
- Auto-allow reads the newest 500 messages of the Sent folder when an unknown sender arrives, instead of hooking outgoing
  mail. A client that keeps no Sent copy teaches nothing.
- The token is random per held message (128 bits). A reply must come from the held message's sender.
- The score bypass reads `X-Spam-Status`, which SpamAssassin and rspamd replace, and only while a spam filter is wired in;
  otherwise a sender could forge it. rspamd gets `milter_headers.conf` for this header, so a host must apply the mail
  policy once.

**Not verified here.** The delivery path ran on real Pigeonhole 2.3.16 with `sieve-test` and a stand-in `sendmail`. A live
LMTP delivery, Postfix re-entry and the EL profiles under SELinux enforcing wait for the native qualification.

## Mailing list moderation

Owner decision 2026-11-07: moderation is built as cPanel. cPanel's Mailman is a daemon that does not fit 1 vCPU / 1 GB, so
the same outcome is built on what already delivers lists here: the Postfix alias table and Dovecot LMTP.

**Delivery.** A list with no stopping rule stays a plain alias and pays nothing. A list with a rule (members-only or moderated
posting, a moderated member, a hold, reject or discard sender rule, a size limit) aliases to a hidden user of the account, the
same nologin kind an autoresponder uses, in the per-account `.invalid` domain that smtpd refuses from outside. LMTP runs as the
account, so the check, the queue and the disk use all belong to the account. The hidden user's Sieve before-script pipes the post
to `xpanel-list-gate` through `vnd.dovecot.execute`, as BoxTrapper does, and reuses that program's parsers and notice limiter.
There is no daemon: a post costs one `node --jitless` start. A host without Pigeonhole's external programs reports
`sieve_extprograms_missing`; a saved limited list then stays undelivered (`restricted`), never open, and saving a new limit there
is refused so a delivering list does not silently stop.

**Order.** Mailman's: a release mark, then a list loop (own `List-Id`, dropped), then automated mail (held without a sender notice),
then a member's own moderation flag, then a non-member's accept, hold, reject and discard rules, then the posting mode, then
the size limit. Moderated posting holds members whatever `memberAction` says, because rejecting every member is not moderation.
The sender is the single address in `From:`. Two authors name no sender, so neither counts as a member. `From:` can be forged, as
it can for Mailman; DKIM and SPF sit in front of the list.

**Fan-out.** The program hands the post to `sendmail` for the members, keeping the envelope sender as the alias did. It drops the
hidden user's `Delivered-To` and `Return-Path`, and adds `List-Id`, `List-Post` and `Precedence: list`, which stop autoresponders
and catch a loop through a member's forwarder, which the static alias graph can no longer see. Subjects and `Reply-To` stay as sent.

**Failure.** Any program failure, a full queue (5000 held) included, exits non-zero, so the Sieve script falls to the implicit keep and
the post lands in the hidden Maildir (256 MB, then the sender gets a bounce). The next queue read adopts it as `gate_failed`. A
post the check could not take therefore reaches no member and is not lost.

**Moderation.** Decisions run as the account through `runuser` under a reviewed grammar, and the API re-validates each answer
because the account can edit those files. Approve re-enters through Postfix to the list address with a one-time mark (a
random id, spent on use), so the current members apply and the spam filter scans it again; if the list has since become a plain
alias, the alias delivers it. Reject sends the moderator's reason to the sender. Discard is silent and asks for confirmation.
The owner works the queue from xPanel. From webmail a moderator mailbox of the account opens it on its own session, as a
cPanel delegate does; anyone else names the list password, under the same five-try lock as member administration.

**State.** The policy lives on the list record in `mailing-lists.json`, so posting mode, members and rules commit and roll back as
one file, and it reaches the host as a root-owned rule file through the mail routing reconcile. Held posts, release marks and the
notice limiter are in `<home>/mail/<domain>/<list>/listgate`, which Maildir++ ignores and account backups carry. Deleting a list
purges them as the account; the audit detail says when that failed.

**Differences from Mailman.**
- Sender rules take `*` and `?` globs instead of regular expressions, for the same reason as BoxTrapper.
- Notices are fixed English text, not per-list templates. Moderator notices stop at 200 a day per list, and each sender gets one
  notice of a kind a day.
- Retention runs at the next delivery, so a quiet list keeps expired posts until mail arrives.
- No periodic reminder of pending posts, no approval by mail, no digest, no `Reply-To` or subject rewriting, no DMARC munging.
- No "add sender to a filter" shortcut from the queue, and no decision log; the audit log records moderator decisions.

**Not verified here.** The program ran against real files with a stand-in `sendmail`. A live LMTP delivery through the hidden user,
Pigeonhole's handling of the `execute` test and of `discard`, Postfix re-entry of an approved post, and the EL profiles under SELinux
enforcing wait for the native qualification.
