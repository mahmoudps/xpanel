# Web statistics (AWStats, Webalizer) and the GeoIP source

Date: 2026-11-07. Scope: cPanel Metrics AWStats and Webalizer per domain (`web-stats-awstats`, `web-stats-webalizer`), Metrics Editor (`metrics-editor`), WHM Statistics Software Configuration (`web-stats-engines`) and the visitor country database (owner decisions 11 and 13).

## Decision

- The engines are the programs cPanel itself runs: AWStats and Webalizer, not a rewrite. A distribution package is used wherever one exists; the installer builds the rest from pinned upstream releases, so no profile is excluded (owner decision 2026-11-07, extending the mpm-itk build of 2026-11-02). Repository check of the profiles (2026-11-07):

  | Profile | AWStats | Webalizer | GeoIP2 Perl module |
  |---|---|---|---|
  | Ubuntu 22.04 | universe 7.8 | universe 2.23.08 | `libgeoip2-perl` |
  | Ubuntu 24.04 | universe 7.9 | universe 2.23.08 | `libgeoip2-perl` |
  | AlmaLinux, Rocky Linux, CentOS Stream 9 | EPEL 9 8.0 | pinned build 2.23-08 (last package in EPEL 8) | `perl-GeoIP2` (EPEL 9) |
  | EL 10 (supported, not a qualification profile) | pinned 8.0 | pinned build 2.23-08 | `perl-GeoIP2` (EPEL 10) |

  The `web-stats` package role lists what each repository has plus the build inputs (`gd-devel`, `libpng-devel`, `zlib-devel`, `make`, all in AppStream on EL 9 and 10; EL 10 adds the Perl modules `awstats.pl` loads). `gcc` is already a bootstrap package.
- Pinned builds in `scripts/el-source-builds.sh`: Webalizer 2.23-08 (`webalizer_2.23.08.orig.tar.gz`, SHA-256 `edaddb5aa41cc4a081a1500e3fa96615d4b41bc12086bcedf9938018ce79ed8d`) and AWStats 8.0 (`awstats_8.0.orig.tar.gz`, SHA-256 `3ef76ff96c5398477dd8a11134e266e538a487067f6906a3ac8a38bfd11c11e0`), fetched from the Debian archive as mpm-itk is; each digest is the one in Debian's signed `.dsc`, and it is checked before anything is unpacked. A failed fetch, digest or build stops the installer, as with mpm-itk. After installation the agent rebuilds them (`2026-11-07-el-source-rebuild.md`).
  - Webalizer: `./configure --disable-dns`, then `make webalizer` only. Debian's GCC 10 patch touches only code under `USE_DNS`, so this build needs neither that patch nor Berkeley DB, and the statistics run never resolves names in Webalizer. `-std=gnu89` is the dialect of the source; EL 10 adds `-fpermissive` for GCC 14. The build applies the `memcpy` to `memmove` change of Debian and Fedora in `preserve.c`, which otherwise corrupts the history once it is full.
  - AWStats: `wwwroot/cgi-bin` is copied to the EPEL path `/usr/share/awstats/wwwroot/cgi-bin`, so all EL releases share one path. The copy closes CVE-2025-63261 with the same one-line change as Debian's patch. EPEL 9's package carries whatever EPEL ships.
  - Other Debian patches are left out: gettext and Apache logio do not apply to a combined log on standard input, and the `.htaccess` symlink fix covers an option the empty configuration leaves off.
  - Build inputs stay installed, as with mpm-itk. Here they also matter at run time: the build is unknown to RPM, so `gd-devel` is what keeps `gd` installed.
  - Budget: both run only inside the installer, and neither adds a service. The compile is sequential; its peak on 1 GB is not yet measured.
- Upgrades: release upgrades and rewinds touch neither `/usr/bin/webalizer` nor `/usr/share/awstats`, because neither lives under `/opt/xpanel`. They also never install packages: after settlement the release package job builds what is missing (`2026-11-07-release-packages.md`) and leaves a present engine alone. A `dnf upgrade` that drops a library or Perl module the build needs is a failure no package database would catch, so the `awstats`, `webalizer` and `web-stats` probes run `perl -c` and `webalizer -V` on an installed engine and fail truthfully, and the agent rebuilds it from the pin. Moving a pin means changing URL and digest together in `scripts/el-source-builds.sh`.
- Input: the bandwidth meter stays the only reader of the edge site logs and owns the read cursor and rotation (w2b-accounts). A tee on its existing analytics feed appends each newly consumed line, converted to the combined log format, to a root-only spool per site and scheme (`/var/lib/xpanel-stats/spool`, 0600). The tee keeps its own identity and end-offset marks, so a meter re-read after a lost ledger write is not spooled twice, and a gap in offsets is reported as log bytes not read. A save that wrote bytes but not its state truncates them before writing again. Each spool is capped at 64 MiB; lines past the cap are counted and shown, never silently lost. The edge JSON line gained `scheme` and `protocol` so SSL and non-SSL are reported apart, as cPanel does.
- Runs: on the saved log processing interval (24 hours by default, cPanel's value), per account and site, each engine runs as the account under `nice -n 19` and `ionice -c 2 -n 7` (the backup runner), with the spool on standard input, a 30-minute bound and no shell. Reports land where cPanel puts them: `~/tmp/awstats` (`ssl/` for HTTPS) and `~/tmp/webalizer[ssl]/<site>`. AWStats reads a root-owned configuration (`/var/lib/xpanel-stats/conf/<user>/<scheme>`, root:account 0640) with `LogFile="-"`, no browser updates, and DNS lookups only when root turns them on. A spool taken by a run records which engines finished it; a retry feeds only the engine that failed. A suspended account keeps its spool until it is active again; a removed site loses it.
- Views: AWStats month data files are read back as the account (`cat` through `runuser`) and reduced to a bounded report (totals, days, hours, countries, operating systems, browsers, status codes, top 25 pages, referrers, robots; 12 months kept) that both themes render on `/metrics/web-stats` (`GET /api/account/web-stats`). Webalizer's own pages and graphs are served unchanged by `GET /api/account/web-stats/webalizer/{scheme}/{site}/{file}`, as cPanel shows them, under `sandbox allow-same-origin; default-src 'none'; img-src 'self'`: the account can edit those files, so no script, form, frame or foreign resource runs. EPEL's `conf.d/awstats.conf` would publish the AWStats CGI to `Require local`, which every visitor proxied by the edge satisfies, so the installer keeps it as an empty managed file.
- GeoIP: DB-IP "IP to Country Lite", MaxMind DB format, licence Creative Commons Attribution 4.0 (attribution "IP Geolocation by DB-IP" with a link to db-ip.com, shown on the page). It is free of account keys and redistribution limits, unlike MaxMind GeoLite2, and updated monthly. Update method: the statistics run downloads `https://download.db-ip.com/free/dbip-country-lite-YYYY-MM.mmdb.gz` once per month (falling back to the previous month before the new release appears), with no redirects, a 16 MiB download and 48 MiB database bound, checks the MaxMind DB metadata (country database type, record size, node count against the file size) and atomically replaces `/var/lib/xpanel-stats/geoip/dbip-country-lite.mmdb` (0644) with its source, month and SHA-256 beside it. A failed download keeps the installed copy. AWStats reads it through its `geoip2_country` plugin. Webalizer only reads the legacy GeoIP format, so its countries stay unresolved. The traffic view shows the country beside each top client address through `lookupGeoipCountry`, a small search-tree reader in `apps/agent/src/geoip.ts`; the file is read for that view only and nothing stays in memory. An address the database does not know stays unresolved. `lookupGeoipCountry` is also the seam for the mail country filter.
- Configuration: `extended/server/web-stats.json` below the state root holds the root policy and every owner choice, written revision-bound under the writer lock and proven by a re-read. A damaged file stops runs, keeps every spool and refuses changes until reviewed. The next run reads it; no reload is involved.
- Metrics Editor (`PUT /api/account/web-stats`): per-site engine switches. A saved choice counts only for an engine the user may still choose; any other engine follows the server default, and changing one is refused with FORBIDDEN (`web_stats_choice_locked`) and nothing saved. An engine turned off receives no lines at the next run and reports `not-selected`.
- Statistics Software Configuration (`GET`/`PUT /api/server/web-stats`, shown on WHM Logs): each engine available and on by default, all users or an allow list, the interval in 0.25 hour steps from 0.25 to 168, blackout hours in UTC, keeping runs apart from backups (on by default: a backup and a run on one vCPU compete for the same disk), the AWStats include and reverse DNS. The 15-minute tick starts a run held back by a blackout hour or a backup at the first allowed moment. Accounts behind schedule are listed with their minutes, and `POST /api/server/web-stats/process` runs one account in the background without moving the schedule.
- The AWStats include is `~/tmp/awstats/awstats.conf.include`, as cPanel. It runs as the account, so it grants nothing the account does not have. AWStats stops on a missing include, so the run creates it first as the account.

## Analog, reseller locks and the bandwidth interval (2026-11-07)

- Analog is a switch, not a third program: its report is the edge-log traffic view, the plan feature is `Analog Stats`, and cPanel's Available, Active by Default and per-user allow list apply to it as to the other engines. Off for a site or a plan, the agent withholds top pages, referrers and client addresses and marks the reply `analog: 'off'`, so the page says not read rather than empty. Totals, the series and bandwidth stay, because the Bandwidth tool reads them.
- A reseller holds an engine on or off for its own accounts on its accounts page (`GET`/`PUT /api/resellers/web-stats`, privilege `edit-account`), saved as `resellerLocks` in the same revision-bound file. A lock outranks the owner's choice and the default, and root's Available outranks a lock. The Metrics Editor shows a locked engine closed and refuses a change with `web_stats_choice_locked`.
- `bandwidthIntervalMinutes` is the spacing the meter reads before each collection, not a second timer. It runs from 5 to 360 in steps of 5: 5 is the meter's shortest spacing and its default, kept over any backlog because one collection reads at most 8 MiB; 360 is the journal window, because a longer spacing would read the mail and FTP journals slower than they are written. Limit enforcement and log rotation follow collection, so a longer interval delays both. cPanel counts this setting in hours; minutes keep the meter's five-minute default expressible.
- The file has no shim for these keys (prelaunch cutover): a `web-stats.json` saved by an earlier build reads as needing review, and its statistics runs stop until root removes it.

## Measurements

Ubuntu 22.04 qualification guest, Node 26.12.1, unprivileged user: converting 100,000 typical edge lines (41,000,000 bytes) to the combined format took 445 to 471 ms wall and 462 to 497 ms CPU (about 4.6 microseconds per line) and produced 19,900,000 bytes. A full meter collection reads at most 8 MiB, about 20,000 lines, so the tee adds about 95 ms CPU per five-minute collection at that ceiling and nothing on an idle site. The spool holds about half the raw log size.

## Open

- Native runs of AWStats 7.8/7.9/8.0 and Webalizer on the profiles, AWStats and Webalizer CPU and memory over a month of logs on a 1 vCPU / 1 GB host, and the GeoIP download from a lab host are not yet measured or qualified. Neither pinned build has run on an EL host: the compile under GCC 11 and 14, the link against `gd`, the complete Perl module list on EL 10, the SELinux labels, and the speed of the pure-Perl MaxMind reader on EL 10 (EPEL 10 has no XS reader) are proven only there.
- Webalizer FTP belongs to `web-stats-ftp`.
- The Debian AWStats and Webalizer packages keep their own cron jobs for the default configurations; they do not read the panel's spools.
