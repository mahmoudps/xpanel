# Public-docs research notes

Implementation facts gathered from public cPanel, WHM, webmail and aaPanel documentation, in our own words. Sources are cited inline. Used by the catalog, plans, reseller ACLs, transfers and the cPanel backup importer.

## cpanel-files-db-domains

- Method: tool inventory taken from the docs.cpanel.net group index pages (https://docs.cpanel.net/cpanel/files/, https://docs.cpanel.net/cpanel/databases/, https://docs.cpanel.net/cpanel/domains/); function names and parameters from the public UAPI OpenAPI data behind api.docs.cpanel.net (index: https://api.docs.cpanel.net/specifications/cpanel.openapi.md). All behaviors above are paraphrased; no prose, code, icons or layouts copied.
- Upstream home-screen inventory (from the Branding::get_available_applications example in the UAPI spec): Files = file manager, images, directory privacy, disk usage, web disk, backup, backup wizard, git; Databases = phpMyAdmin, MySQL databases, MySQL wizard, remote MySQL; Domains = site publisher, domains, addon domains, subdomains, aliases, redirects, zone editor. FTP Accounts, FTP Connections, Anonymous FTP, File Restoration, PostgreSQL, Dynamic DNS appear conditionally on server roles/features. Source: https://api.docs.cpanel.net/specifications/cpanel.openapi.md
- Version drift to respect: 'MySQL Databases' became 'Manage My Databases' (v120+), 'MySQL Database Wizard' became 'Database Wizard', 'Remote MySQL' became 'Remote Database Access' (v118+); MySQL Manager removed in v122; Site Publisher removed in v134 (Sitejet replaces it); the separate Addon Domains/Subdomains/Aliases pages are folded into the unified Domains page (docs 138+). Sources: https://docs.cpanel.net/cpanel/databases/manage-my-databases/ , https://docs.cpanel.net/cpanel/databases/mysql-manager/ , https://docs.cpanel.net/cpanel/domains/site-publisher/ , https://docs.cpanel.net/cpanel/domains/domains/
- Feature-key names actually documented in the public API text: filemanager, ftpaccts (FTP Accounts and Anonymous FTP), addondomains, mysql, redirects, backup; others are only given as display names in Feature Manager (e.g. 'Disk Usage Viewer', 'Backup Manager', 'Alias Domains', 'Simple Zone Editor (A and CNAME)', 'Advanced Zone Editor (all except MX)', 'Manage DNSSEC', 'Dynamic DNS', 'File and Directory Restoration', 'PhpMyAdmin', 'PostgreSQL', 'Web Disk', 'FTP Account Manager', 'FTP Settings', 'Git Version Control'). Our catalog should mint its own keys. Sources: https://docs.cpanel.net/whm/packages/feature-manager/ and https://api.docs.cpanel.net/specifications/cpanel.openapi.md
- Reseller ACLs relevant to this area (WHM side): allow-addoncreate and allow-parkedcreate gate plans with addon/alias allowances; create-dns, kill-dns, park-dns, edit-dns, manage-dns-records gate zone work; file-restore gates the WHM file restoration tool. Source: https://api.docs.cpanel.net/guides/guide-to-whm-plugins/guide-to-whm-plugins-acl-reference-chart
- Reserved home subfolders that cannot be a document root or Git path (adopt our own equivalent list): .cpanel, .trash, etc, mail, ssl, tmp, logs, .cphorde, spamassassin, .htpasswds, var, cgi-bin, .ssh, perl5, access-logs. Git paths also reject whitespace and \ * | " ' < > & @ ` $ { } [ ] ( ) ; ? : = % #. Document roots must stay inside public_html when the restriction is on. Sources: https://docs.cpanel.net/cpanel/files/git-version-control/ , https://docs.cpanel.net/cpanel/domains/domains/create-a-new-domain/
- Addon domain model: an addon = a backing subdomain of the main domain + the new name parked on it; creation must be atomic (roll back subdomain if park fails); it also creates an FTP user counted against the FTP limit; deleting a subdomain that still backs an addon must be refused; removing a domain removes vhost+DNS but never files. Source: https://api.docs.cpanel.net/specifications/cpanel.openapi/addondomain/addondomain-addaddondomain.md and https://api.docs.cpanel.net/specifications/cpanel.openapi/subdomain/subdomain-addsubdomain.md
- Document-root change: target folder must already exist, files are not moved, aliases on that host follow the new root, and an empty new root breaks HTTP-01 certificate renewal (surface a warning). Source: https://api.docs.cpanel.net/specifications/cpanel.openapi.md (SubDomain::changedocroot)
- Domain rename: allowed for main, addon and alias (not subdomain); new name must not exist; only one rename in flight; updates config, docroot paths and DNS. Source: https://api.docs.cpanel.net/specifications/cpanel.openapi/domain/domain-rename_domain.md
- MySQL/MariaDB naming: database name max 64 with each underscore costing 2 (wildcard escaping in grants) and prefix '<user>_' counted; username caps incl. prefix: MySQL 5.6 = 16 (prefix 8+_), MySQL 5.7+ = 32 (prefix 16+_), MariaDB = 47 (full username+_); optional 8-char short prefix. Privilege set: ALTER, ALTER ROUTINE, CREATE, CREATE ROUTINE, CREATE TEMPORARY TABLES, CREATE VIEW, DELETE, DROP, EVENT, EXECUTE, INDEX, INSERT, LOCK TABLES, REFERENCES, SELECT, SHOW VIEW, TRIGGER, UPDATE or ALL PRIVILEGES; setting privileges replaces the list. Sources: https://docs.cpanel.net/cpanel/databases/manage-my-databases/ , https://api.docs.cpanel.net/specifications/cpanel.openapi/user-management/mysql-set_privileges_on_database.md
- Remote DB host formats accepted: single IP, % wildcard (e.g. 192.168.%.%), CIDR (e.g. 192.168.0.0/16), hostname, IPv6; note up to 255 ASCII chars. Sources: https://docs.cpanel.net/cpanel/databases/remote-database-access/ , https://api.docs.cpanel.net/specifications/cpanel.openapi/remote-databases/mysql-add_host.md
- PostgreSQL: names and usernames max 63 incl. prefix, password min 5 chars; linking grants all privileges; because PostgreSQL lacks recursive/future grants, provide a 'Synchronize Grants' action that re-grants on all tables; renaming a user invalidates the md5 hash so a new password is required. Source: https://docs.cpanel.net/cpanel/databases/postgresql-databases/
- Never let databases/users be created inside phpMyAdmin/phpPgAdmin outside the panel's mapping (breaks backup/restore). phpPgAdmin upstream is largely unmaintained; consider a maintained OSS client behind the same SSO. Sources: https://docs.cpanel.net/cpanel/databases/manage-my-databases/ , https://docs.cpanel.net/cpanel/databases/phppgadmin/
- Password strength: 0-100 score with per-service minimums; services with separate minimums include createacct, ftp, htaccess, mysql, passwd, pop, postgres, sshkey, webdisk, virtual. Source: https://api.docs.cpanel.net/specifications/cpanel.openapi.md (PasswdStrength::get_required_strength)
- FTP: quota unit is MB and 0 means unlimited; delete has a 'destroy home folder' flag; account types main, sub, logaccess, anonymous; default homedir derives from the login; dot-stripping option on usernames; FTPS has no SNI so clients should connect by server hostname; Pure-FTPd lists at most 10,000 entries per folder by default; quotas unavailable on ProFTPD. Sources: https://docs.cpanel.net/cpanel/files/ftp-accounts/ , https://api.docs.cpanel.net/specifications/cpanel.openapi/ftp-accounts/ftp-add_ftp.md
- Web Disk: WebDAV on TLS port 2078 per docs; min password 5 chars; permissions rw/ro; delete has destroy flag; digest auth is an opt-in per account for non-TLS Windows clients and is invalidated by user/domain rename. Sources: https://docs.cpanel.net/cpanel/files/web-disk/ , https://api.docs.cpanel.net/specifications/cpanel.openapi/webdisk-settings/webdisk-set_permissions.md
- File Manager limits: in-browser edit only up to 1 MB; archives zip/gz/bz2; upload default mode 0644, explicit overwrite flag, target dir auto-created; trash records original paths (bookkeeping file at trash root), restore picks newest copy and fails if target exists; empty_trash supports older_than days. Sources: https://docs.cpanel.net/cpanel/files/file-manager/ , https://api.docs.cpanel.net/specifications/cpanel.openapi/manage-files/fileman-upload_files.md , https://api.docs.cpanel.net/specifications/cpanel.openapi/trash/trash-usage.md
- Backups: full backup filename pattern date+time .tar.gz; destinations homedir, FTP active/passive (default port 21), SCP by password or key; option to skip homedir; email on completion; partial backups = home tar.gz, per-DB SQL gz, forwarders, account-level filters; full restore is admin-only; restore jobs have timeouts (files 48h, DB 2h defaults); an exclude-list file in home trims the home archive; backups fail near quota. Sources: https://docs.cpanel.net/cpanel/files/backup-for-cpanel/ , https://api.docs.cpanel.net/specifications/cpanel.openapi/backup/backup-fullbackup_to_homedir.md
- Website (per-site) backups (v138 API): background job with operation id, one op per account, quota pre-check, 2h cap for backup/extract and 6h for restore, merge vs clean restore, DB restore resets to dump with a rollback snapshot. Matches the plan's rule that restore must not delete files absent from the archive by default (merge). Source: https://api.docs.cpanel.net/specifications/cpanel.openapi/websitebackup/websitebackup-create_backup.md
- File restoration backup IDs: YYYY-MM-DD (daily), incremental, weekly/YYYY-MM-DD, monthly/YYYY-MM-DD; paths must start with '/', relative to home; mail and panel config folders excluded; overwrite flag required. Sources: https://api.docs.cpanel.net/specifications/cpanel.openapi/file-restoration/restore-restore_file.md , https://docs.cpanel.net/cpanel/files/file-and-directory-restoration-for-cpanel/
- Git deployment file: YAML at repo root with a deployment.tasks list of shell commands run in order; a post-receive hook auto-deploys on push; manual flow = fast-forward pull then deploy HEAD; requires at least one branch and clean tree; SSH remotes require host-key approval into known_hosts. Name our own file (e.g. .xpanel.yml) and consider reading the upstream name for imports. Sources: https://docs.cpanel.net/knowledge-base/web-services/guide-to-git-deployment/ , https://docs.cpanel.net/cpanel/files/git-version-control/
- Redirect API semantics: type permanent|temp; www mode 0 = with and without www, 1 = without www only, 2 = with www only; wildcard flag; default source path '/'; stored as Redirect/RedirectMatch in .htaccess. Upstream appends to the bottom of .htaccess, which apps like WordPress can shadow; we should write a managed block placed before app rewrite blocks. Sources: https://api.docs.cpanel.net/specifications/cpanel.openapi/domain-redirection/mime-add_redirect.md , https://docs.cpanel.net/cpanel/domains/redirects/
- Zone editing: batch API takes add/edit/remove arrays keyed by zone line index and requires the current SOA serial (optimistic concurrency); reset rebuilds from the server template and loses hand-added records; ALIAS only on PowerDNS (fits our PowerDNS stack); temporary domains cannot be edited. Sources: https://api.docs.cpanel.net/specifications/cpanel.openapi/dns/dns-mass_edit_zone.md , https://api.docs.cpanel.net/specifications/cpanel.openapi/zoneedit/zoneedit-resetzone.md , https://docs.cpanel.net/cpanel/domains/zone-editor/
- DNSSEC defaults: algorithm 8 (RSA/SHA-256) with classic KSK 2048 / ZSK 1024; algorithms 13/14 use simple (single CSK) setup; NSEC3 default iterations 0 in current versions (max 500), salt '-' meaning none, narrow mode on, opt-out off; keys cannot be modified, only replaced. Sources: https://api.docs.cpanel.net/specifications/cpanel.openapi/dns-security/dnssec-enable_dnssec.md , https://docs.cpanel.net/cpanel/domains/zone-editor/
- Dynamic DNS: each entry has a random 32-letter lowercase ID used in the update URL; 'recreate' issues a new ID; last_update_time changes only on IP change while last_run_times record every call. Docs do not specify how the IP is derived; we define it as the caller's source address unless an explicit IP is passed. Sources: https://api.docs.cpanel.net/specifications/cpanel.openapi/dynamic-dns/dynamicdns-create.md , https://docs.cpanel.net/cpanel/domains/dynamic-dns/
- Site Publisher safety model worth keeping for our own templates: archive the docroot before publishing, abort on archive failure, restore on write failure, retain archives 30 days, keep settings JSON outside docroot. Source: https://docs.cpanel.net/cpanel/domains/site-publisher/
- Wildcard subdomains are not described in the current cPanel user docs; xPanel defines them as a '*' DNS record plus ServerAlias with explicit subdomains taking precedence (C:\Development\xpanel\docs\PLAN.md). Addon domains must reject wildcards per https://api.docs.cpanel.net/specifications/cpanel.openapi/addondomain/addondomain-addaddondomain.md
- Server-role gating seen upstream (functions disabled when role off): File Storage (Fileman, Restore), Web Server (domains, redirects, images), FTP, MySQL/MariaDB (unless remote DB configured), PostgreSQL, DNS (zone, DNSSEC, DDNS), Web Disk. Map these to xPanel service availability so tools hide when the service is absent. Source: https://api.docs.cpanel.net/specifications/cpanel.openapi.md

## cpanel-email-metrics-security

- Mail filter model (Exim based): rule parts = From, Subject, To, reply address, body, all headers, any recipient (To+CC), not-delivered, bounce/error message, List-Id, spam status, spam bar (count of + chars), spam score. String ops: is, matches (PCRE), contains, does not contain, begins, does not begin, ends, does not end, does not match; numeric ops: is above, is not above, is below, is not below. Actions: deliver (redirect), save (folder), fail (bounce with text), finish (stop processing), pipe, discard. Rules join with and/or where 'and' binds tighter. Parameters are numbered (part1/match1/val1/opt1/action1/dest1). BCC cannot be matched; backslashes may need doubling; body newlines become spaces. Source: https://docs.cpanel.net/knowledge-base/email/how-to-configure-email-filters/ and https://api.docs.cpanel.net/specifications/cpanel.openapi.md (Email::store_filter).
- Mailbox quota: integer MB in the API (UI offers MB..PB), cap 4096 TB, 0/unlimited only when the plan has no per-mailbox maximum; trash excluded; full mailbox bounces new mail. Reserved local part 'cpanel'. Restrictions matrix: receive allow/suspend; send allow/suspend/hold (hold queues, release delivers); login allow/suspend. Sources: https://docs.cpanel.net/cpanel/email/manage-email-accounts/ and Email::add_pop/edit_pop_quota in https://api.docs.cpanel.net/specifications/cpanel.openapi.md
- Forwarder and default-address modes map to fwd, fail, system, pipe, blackhole. Pipes: path relative to home, executable, mode 0700, any stdout makes a bounce. Domain forwarders beat the catch-all. Sources: https://docs.cpanel.net/cpanel/email/forwarders/, https://docs.cpanel.net/cpanel/email/default-address/
- Email routing values: auto, local, secondary (backup), remote; auto reads only the local zone, not live DNS, and is not re-run when MX changes. Source: https://docs.cpanel.net/cpanel/email/email-routing/ and Email::set_always_accept.
- Autoresponder: interval hours >= 0 (0 = every message), one per address, stop > start, charset default utf-8, placeholders for incoming subject/sender name/sender address, no reply when spam score >= 5. Source: https://docs.cpanel.net/cpanel/email/autoresponders/
- Track Delivery: 250 newest rows by default; retention set by admin, 1-365000 days; status types success, in-progress, deferred, error, archived, rejected, filtered. Source: https://docs.cpanel.net/cpanel/email/track-delivery/
- Spam: threshold default 5, must be > 0 (Email::add_spam_filter); allow/deny entries take * and ? wildcards; per-test score overrides up to 3 decimals, 0 disables a test (SpamAssassin::update_user_preference with preference score/required_score/whitelist_from/blacklist_from). Spam box folder name 'spam'. Source: https://docs.cpanel.net/cpanel/email/spam-filters/
- Sender verification (BoxTrapper equivalent): bypass spam score default -2.5; templates verify, verifyreleased, returnverify, blacklist; ignore list beats allow list. Source: https://docs.cpanel.net/cpanel/email/boxtrapper/. We use our own name and do not reuse the BoxTrapper brand.
- Greylisting defers unknown (IP, sender, recipient) triplets, default 5 minutes. Source: https://docs.cpanel.net/cpanel/email/configure-greylisting/
- Archive folders are named <type>.YYYY-MM-DD in GMT under the mail dir; types are incoming, outgoing, mailing list; access is read-only IMAP (993/143) plus zip download. Source: https://docs.cpanel.net/cpanel/email/archive/
- Mail client ports: IMAP 993/143, POP3 995/110, SMTP 465/587; secure host is the domain if it has a valid cert, otherwise the server hostname. CalDAV/CardDAV served over HTTPS on port 2080 with /principals/<address>, /calendars/<user>/calendar, /addressbooks/<user>/addressbook. Sources: https://docs.cpanel.net/cpanel/email/set-up-mail-client/, https://docs.cpanel.net/knowledge-base/webmail/how-to-set-up-calendars-and-contacts/
- DAV collections: types calendar, tasks, addressbook; on create the path is auto-generated as <type>-<uuid>; shares carry a readonly flag (CPDAVD::manage_collection, CPDAVD::add_delegate). Calendar Delegation was renamed to Calendars and Contacts Sharing in v120. Source: https://docs.cpanel.net/cpanel/email/calendar-delegation/
- Address importer: .csv/.xls/.txt; column roles email/password/domain/ignore; import type email or fwd; password strength >= 65; quota in MB. Source: https://docs.cpanel.net/cpanel/email/address-importer/
- Email Disk Usage cleanup presets: >= 1 year old, >= 30 MB, seen, all, custom IMAP-style query; the API requires a non-empty query so a mailbox cannot be wiped by accident. Source: https://docs.cpanel.net/cpanel/email/email-disk-usage/
- GnuPG: key size 1024/2048/3072/4096 (default 2048), expiry default 1 year or no_expire; delete private before public. Source: https://docs.cpanel.net/cpanel/email/encryption/ and GPG::generate_key.
- Email Deliverability: SPF builder supports a, mx, ip4/ip6 CIDR, include, ~all default vs -all; DKIM view splits into 255-char chunks; DMARC needs valid SPF+DKIM; repair only when this server is authoritative for the zone. Source: https://docs.cpanel.net/cpanel/email/email-deliverability-in-cpanel/
- Bandwidth: protocols http, imap, smtp, pop3, ftp; samples at 5min, hourly, daily with per-interval retention (Bandwidth::get_retention_periods); only sent SMTP counts; file-manager, inbound mail, polling, DNS and cron traffic are excluded. Source: https://docs.cpanel.net/cpanel/metrics/bandwidth/
- Raw logs: archive after stats run (daily default) into ~/logs; prune last month's archives; retention_days 0 = keep forever, -1 = server default, positive = days. Source: https://docs.cpanel.net/cpanel/metrics/raw-access/ and LogManager::set_settings.
- Errors view caps at 300 newest lines. Source: https://docs.cpanel.net/cpanel/metrics/errors/. Visitors optional columns are status, method, protocol. Source: https://docs.cpanel.net/cpanel/metrics/visitors/
- ResourceUsage::get_usages ids: disk_usage, filesusage, cachedmysqldiskusage, cachedpostgresdiskusage, bandwidth, addon_domains, subdomains, aliases, email_accounts, mailing_lists, autoresponders, forwarders, email_filters, ftp_accounts, mysql_databases, postgresql_databases; maximum is null when unlimited. Use it as the single source for plan-limit checks (LIMIT_EXCEEDED). Source: https://api.docs.cpanel.net/specifications/cpanel.openapi.md
- SSH key generation (API 2 SSH::genkey): bits >= 1024, type rsa (default) or dsa, passphrase >= 4 chars, reserved names config, known_hosts, authorized_keys, environment, rc, identity, user. Our rebuild should add ed25519 and make it the default. Source: https://api.docs.cpanel.net/cpanel-api-2/cpanel-api-2-modules-ssh/cpanel-api-2-functions-ssh-genkey.md
- IP Blocker inputs: single, a-b range, implied range a.b.c.d-e, CIDR, prefix 'a.', hostname; stored as CIDR deny rules in .htaccess; applies to websites only. Source: https://docs.cpanel.net/cpanel/security/ip-blocker/
- Hotlink API: urls newline-separated, extensions comma-separated, allow_null 0/1, redirect_url. Leech protection API 2 items: numhits (logins per user per 2 h), url, email, kill. Sources: Mime::add_hotlink in the UAPI spec; https://api.docs.cpanel.net/cpanel-api-2/cpanel-api-2-modules-leechprotect/cpanel-api-2-functions-leechprotect-setup.md
- SSL key types: system, rsa-2048, rsa-4096, ecdsa-prime256v1, ecdsa-secp384r1 (SSL::generate_key). Self-signed requires domains, city, state, country, company. Changing the default key type triggers an auto-certificate run. Status filters: domain type, cert type (unsecured/self-signed/auto DV/DV/OV/EV), status (active/expired/expiring/unsecured/auto problems), auto included/excluded. Sources: https://docs.cpanel.net/cpanel/security/ssl-tls/, https://docs.cpanel.net/cpanel/security/ssl-tls-status/
- API tokens: name <= 50 chars [A-Za-z0-9_-], unique; secret is 32 uppercase alphanumerics shown once; expires_at unix timestamp or never (UI default 1 year, end of day server time); readonly=1 rejects writes; header 'Authorization: cpanel <user>:<token>'; expired tokens are not auto-deleted. Sources: https://docs.cpanel.net/cpanel/security/manage-api-tokens-in-cpanel/, https://api.docs.cpanel.net/cpanel/tokens.md
- 2FA: TwoFactorAuth::generate_user_configuration returns a 16-char secret and an otpauth URL for the QR code; set_user_configuration takes secret + 6-digit tfa_token; reconfigure logs out other sessions. Source: https://docs.cpanel.net/cpanel/security/two-factor-authentication-for-cpanel/
- ModSecurity per-domain toggles only work after it is enabled for all domains. Source: https://docs.cpanel.net/cpanel/security/modsecurity/
- Group membership and tile ids (appkeys) from https://api.docs.cpanel.net/guides/guide-to-cpanel-interface-customization-and-branding/guide-to-cpanel-interface-customization-appkeys.md: Email = email_accounts, forwarders, email_routing, autoresponders, default_address, mailing_lists, track_delivery, global_email_filters, email_filters, email_deliverability, address_importer, apache_spam_assassin, archive, encryption, boxtrapper, greylisting, calendar_and_contacts, manage_calendar_access, calendar_contact_management, email_disk_usage. Metrics = visitors, site quality (vendor), errors, bandwidth, raw_access, awstats, analog_stats, webalizer, webalizer_ftp, metrics_editor, cpu_and_concurrent_connection_usage (CloudLinux). Security = ssh_access, ip_blocker, ssl_tls, ssl_tls_unified (v134+), api_tokens, hotlink_protection, leech_protection, security_policy, tls_wizard, mod_security, tls_status, two_factor_authentication. Use our own ids and icons; do not reuse the vendor icon assets.
- Feature keys: only a few internal keys are in public docs (the Features::list_features example lists blockers, boxtrapper, changemx, defaultaddress, email_disk_usage, emailarchive, emailauth, emaildomainfwd, emailtrace, popaccts, spamassassin, spambox, traceaddy, webmail; apitokens, sslinstall, autossl and bandwidth also appear in the API spec). The mapping from each key to a tool (for example emailtrace to Track Delivery, blockers to Email Filtering Manager, changemx to Email Routing) is my inference and is not stated in the docs. Where no key is documented, featureKey holds the Feature Manager display name from https://docs.cpanel.net/whm/packages/feature-manager/. resellerAcl is empty for every tool because these are user-level (xPanel) tools.
- Out of scope but listed: Resource Usage and CPU/Concurrent Connections (CloudLinux), Site Quality Monitoring (paid vendor), SSL/TLS Wizard (cPanel Store), Imunify360. Version references: UAPI spec 11.138.0.10 (https://api.docs.cpanel.net/specifications/cpanel.openapi.md); docs pages current for v126-134+.

## cpanel-software-advanced-prefs

- Jupiter group layout. Software: PHP PEAR Packages, Perl Modules, RubyGems (removed), Ruby on Rails (removed), Site Software (removed), Optimize Website, Application Manager, MultiPHP Manager, MultiPHP INI Editor. Advanced: Terminal, Cron Jobs, Track DNS, Indexes, Error Pages, Apache Handlers, MIME Types, Virus Scanner, API Shell. Preferences: Account Preferences, Password & Security, Change Language, Contact Information, User Manager, Manage Team. Each page has a stable app key that can be our route/menu id: php_pear_packages, perl_modules, ruby_gems, ruby_on_rails, site_software, optimize_website, application_manager, multiphp_manager, multiphp_ini_editor; terminal, cron_jobs, track_dns, indexes, error_pages, apache_handlers, mime_types, clam_av, api_shell; account_preferences, change_password, change_language, contact_information, user_manager, team_manager; group ids group_software, group_advanced, group_perf. Sources: https://api.docs.cpanel.net/guides/guide-to-cpanel-interface-customization-and-branding/guide-to-cpanel-interface-customization-appkeys and the index pages https://docs.cpanel.net/cpanel/software/ , /cpanel/advanced/ , /cpanel/preferences/
- Version history to match: Site Software (cPAddons) was removed in v126; RubyGems and Ruby on Rails were removed in v136 and replaced by Application Manager; Change Language is deprecated, and Account Preferences has a language picker from v128; Contact Information and password change were added to Account Preferences in v130. Since 2026 the API docs call Web Apps (UAPI WebApp, container-based, Git or archive source, async deploy) the recommended way to deploy new apps over Application Manager (PassengerApps). Sources: the software pages under https://docs.cpanel.net/cpanel/software/ , https://docs.cpanel.net/cpanel/preferences/change-language/ , https://api.docs.cpanel.net/specifications/cpanel.openapi/web-apps/webapp-stage
- Our replacement for CloudLinux 'Setup Node.js/Python/Ruby App' and 'Select PHP Version' is Application Manager + Web Apps + MultiPHP Manager/INI Editor. Application Manager needs an app server (Passenger-style) module, an optional env module for environment variables, and at least one Node.js runtime and/or Python with pip. The default Python is /usr/bin/python3, then /usr/bin/python, and the admin can override it in one config file. Installing a new Node.js runtime replaces the old one, so existing apps must be moved to it. Source: https://docs.cpanel.net/cpanel/software/application-manager/
- Feature Manager mechanics for xWHM: feature lists are named sets of on/off features attached to packages. There are three built-in lists. 'default' applies to accounts with no custom list. 'Mail Only' gives only mail-related features. 'disabled' is a server-wide block list: anything in it is off for every account whatever its own list says, and it must never be assigned to a package. In the 'disabled' list a checked box means 'blocked', the opposite of other lists. Deleting a list moves its packages and accounts to 'default'. Resellers only see lists they own. Some entries only appear when a dependency exists (FTP server, PostgreSQL, ClamAV plugin, greylisting, 2FA, ea-nginx, license tier). Source: https://docs.cpanel.net/whm/packages/feature-manager/
- Feature list data model (WHM API 1). get_feature_names and get_feature_metadata return {id, name, is_plugin}. get_featurelist_data returns, for each feature: id, name, value (1 = included; inverted for 'disabled'), is_disabled (blocked server-wide), dependencies (other feature ids), is_standalone_experience + redirect_url (feature that takes over the login), only_one_rules (regexes over feature ids that may not be enabled together), required_package_extension, badge_label, is_meridian_only. Per-account overrides: add_override_features_for_user / remove_override_features_for_user; get_users_features_settings shows the list value and the per-user override, and the override wins. - Apache MPM and Global Configuration fields (our own explanation): Only one MPM can be built in; prefork is used when none is chosen; event is preferred when threads and safe polling exist, worker when threads are needed without safe polling; embedded (DSO) PHP and the per-user ITK module require prefork. StartServers (default 5) = child processes forked at start. MinSpareServers / MaxSpareServers (5 / 10, prefork only) = floor and ceiling of idle children; parent forks or kills to stay in range. ServerLimit (256) = hard upper bound for process slots fixed for the life of the parent; MaxRequestWorkers may not exceed it without a full restart. MaxRequestWorkers (150) = maximum simultaneous requests: under prefork it equals max children, under worker/event it is the total thread count (real bound ServerLimit x ThreadsPerChild); the vendor UI validates MaxRequestWorkers <= ServerLimit. MaxConnectionsPerChild (10000, 0 = never) = connections a child serves before it is recycled (memory-leak guard). KeepAlive (Off) = reuse a TCP connection for several requests; KeepAliveTimeout (5 s) = wait for the next request on a kept-alive connection; MaxKeepAliveRequests (100, 0 = unlimited) = requests per connection; these three are also written into the NGINX proxy (unlimited becomes 1000; KeepAlive On maps to keepalive 32 upstream). Timeout (300 s) = I/O wait before a request fails. Threaded-only directives not exposed by the vendor UI (community-reported; override via include): ThreadsPerChild = threads per child, ThreadLimit = cap for ThreadsPerChild, MinSpareThreads / MaxSpareThreads = idle-thread floor/ceiling. xPanel should show prefork fields only under prefork, thread fields only under worker/event, and validate MaxRequestWorkers <= ServerLimit*ThreadsPerChild and divisible by ThreadsPerChild. Other Global fields: SSL cipher suite, SSL/TLS protocols (default all minus SSLv2/SSLv3/TLSv1/TLSv1.1), OCSP stapling On, ExtendedStatus On, LogLevel warn, combined/common LogFormat, TraceEnable Off, ServerSignature Off, ServerTokens, FileETag None, Directory '/' Options (ExecCGI FollowSymLinks IncludesNOEXEC Indexes), Symlink protection Off; settings persisted in one EA config file and applied by rebuild + restart. - PHP-FPM pool fields (our own explanation, standard PHP-FPM semantics): pm = process-manager mode: static (always exactly max_children workers), dynamic (start_servers at boot, keep idle workers between min_spare_servers and max_spare_servers, never exceed max_children), ondemand (no idle workers; fork on request up to max_children, reap workers idle longer than process_idle_timeout). max_children = hard cap of concurrent workers = maximum concurrent PHP requests for that pool (main RAM driver: ~max_children x per-worker RSS). start_servers = workers created at pool start (dynamic only; must be between min and max spare). min_spare_servers / max_spare_servers = idle worker floor and ceiling (dynamic only). max_requests = requests a worker serves before being respawned (leak protection; 0 = never). process_idle_timeout = seconds an idle worker survives (ondemand). Vendor UI exposes only Max Children (default 5, range 1-10000), Max Requests (default 20, 1-10000000) and Process Idle Timeout (default 10 s, 1-10000000) at system and per-domain level; a community post reports default pm = ondemand. System defaults live in an optional system-pool YAML that is merged with per-domain YAML to generate one pool .conf per domain under that PHP version's php-fpm.d (generated files must not be hand-edited); once a domain's pool is edited it no longer follows system defaults. Pool-level INI keys: allow_url_fopen, log_errors, short_open_tag, error_log, disable_functions, error_reporting, each with a lock: locked -> php_admin_value (app cannot override), unlocked -> php_value. Enable-on-all-domains is offered only when RAM is sufficient. Sources: https://docs.cpanel.net/whm/software/multiphp-manager-for-whm-system-settings/ , https://docs.cpanel.net/whm/software/multiphp-manager-for-whm-user-domain-settings/ , https://docs.cpanel.net/knowledge-base/php-fpm/php-fpm-code-and-filesystem-layout-for-easyapache-4/ , https://support.cpanel.net/hc/en-us/community/posts/30216288309271-How-to-find-the-pm-Process-Manager-setting-in-my-PHP-FPM
- PHP handler trade-offs (paraphrased): CGI - runs as the vhost owner only when suEXEC is present, otherwise as nobody; Apache php_value directives do not work (needs per-user php.ini); response headers cannot be set from .htaccess. Embedded/DSO - PHP inside the Apache process, needs prefork, scripts run and create files as nobody (hard to attribute abuse, cross-account data exposure), supports php_value, only one PHP version can use it and it is unsupported for PHP 8.0+. suPHP - runs as the vhost owner with many security checks (docroot, min uid, umask), scripts need 0640+, opcode caches give no benefit, Apache directives unusable, incompatible with ITK/ruid2. LSAPI - fast and stable, included, but full features (opcache preservation) need CloudLinux; incompatible with ITK/ruid2. FPM (proxy_fcgi) - fast, per-pool process management, emergency restart, IP restrictions, customizable via .user.ini, headers from .htaccess work, may need FastCGI tuning; best default for multi-tenant hosting with per-user pools. FCGId - spawns several persistent instances for concurrency, for advanced admins only, incompatible with ITK/ruid2. Recommendation for xPanel: default to FPM with per-user pools running as the account user, keep CGI as fallback, do not offer DSO for PHP 8+. Source: https://docs.cpanel.net/ea4/php/php-handlers/
- NGINX reverse proxy and caching behavior (our own summary): NGINX takes ports 80/443 and proxies every request to Apache over HTTP/1.1 on localhost; Apache moves to the first free port below 1024 (normally 81 for HTTP); custom Apache ports are ignored. Files beginning with .ht are refused. Logs go to /var/log/nginx/domains (bandwidth in *-bytes_log, rotated by logrotate) and Apache does not log proxied requests. ## webmail-aapanel-backup-layout

- cPanel full account archive layout (https://docs.cpanel.net/knowledge-base/backup/backup-tarball-contents/, valid for v102 to current). One USER.tar.gz with one top-level folder. The page itself says not to treat the layout as a stable integration contract, so the xPanel importer must ignore unknown entries and cope with missing ones.
- Archive data folders: homedir/ = copy of the user's home (public_html is the main docroot; homedir/ssl holds the ssl, sslcerts and sslkeys material). mysql/ = one SQL dump per database (USER_db.sql). mysql.sql = MySQL grants. mysql-timestamps/ = database creation times. psql/ = PostgreSQL tar dumps plus a users file and a grants file. dnszones/ = one DOMAIN.db zone file per domain. dnssec_keys/ = per-domain DNSSEC keys. domainkeys/ = DKIM private and public keys. cron/ = the crontab. logs/ = copies of the domain access logs. bandwidth_db.json and bandwidth_db.data.json = bandwidth data (bandwidth/ and bandwidth_db/ are empty legacy folders). counters/ = hit-counter data.
- Archive account-metadata entries: cp/ = the account's user file from /var/cpanel/users (plan, limits, owner, settings). userdata/ = per-domain and subdomain vhost data from /var/cpanel/userdata/USER. addons = addon domain to subdomain map. pds = parked/alias domains. sds = subdomain list. sds2 = subdomain to docroot map. apache_tls/ = per-domain key and cert bundles. sslcerts/ = DOMAIN.crt, .cabundle, .csr. sslkeys/ = DOMAIN.key. autossl.json = AutoSSL preferences. httpfiles/ = custom vhost templates. ips/related_ips = IPv6 addresses. shadow = the system password hash. shell = login shell. quota = disk quota in bytes. homedir_paths = home path. nobodyfiles = files owned by nobody. digestshadow = WebDisk digest passwords. proftpdpasswd = FTP accounts file. version = packager version and archive format version. suspended/ and suspendinfo/ = suspension state. userconfig/ = per-user config copies. locale/ = custom locale. customizations/ = reseller theme JSON. authnlinks/ = external login links. ccs/ = calendar/contacts server data. webcalls.json = dynamic DNS and similar web calls. resellerconfig/, resellerfeatures/, resellerpackages/ = reseller ACLs, nameservers, feature lists and packages (only when the account is a reseller).
- Archive mail entries: va/ = per-domain mail alias data (the docs call it the account's autoresponders; the files come from the /etc/valiases alias tables, so the importer should parse them as alias tables covering forwarders, pipes, fail and blackhole entries plus autoresponder hooks). vad/ = virtual domain aliases. vf/ = per-domain account-level Exim filter files (user-level filters live in the home folder). mm/, mma/pub, mma/priv, mms/ = Mailman lists, public and private archives, and suspended lists. The tarball page does not list mail folders. cPanel's support knowledge base (support.cpanel.net article 1500001449702, and 4639901121175 on mail passwd/shadow) says mailboxes live in homedir/mail/<domain>/<user>/ as Maildir (cur, new, tmp and dot-folders such as .Sent, .Trash, .spam), and per-domain mail credentials live in homedir/etc/<domain>/passwd, shadow and quota. Those support pages could not be fetched directly, so treat this as secondhand until it is checked against a real archive.
- Archive naming and restore (https://docs.cpanel.net/whm/transfers/transfer-or-restore-a-cpanel-account/): accepted names are cpmove-USER, cpmove-USER.tar, cpmove-USER.tar.gz, USER.tar, USER.tar.gz, and backup-MM.DD.YYYY_HH-MM-SS_USER.tar(.gz) (hyphen or underscore separators). The file must be in /home, /home2, /home3, /root, /usr, /usr/home or /web, and free space must be at least twice the archive size. Restore options: overwrite an existing account with the same name; replace all matching A records (default) or only the A records cPanel generated; optional dedicated IP. Restricted restore (on by default) skips unsafe parts, skips parked and addon domains, and forces noshell or jailshell. 2FA settings are not carried over. Account backups listed in cPanel use the backup-MM-DD-YYYY form (https://docs.cpanel.net/cpanel/files/backup-for-cpanel/).
- Scheduled backup settings (https://docs.cpanel.net/whm/backup/backup-configuration/): types are compressed, uncompressed, and incremental (a hard-linked tree that only works with rsync destinations). Default directory is /backup, with a separate staging folder. Daily, weekly and monthly schedules (monthly on the 1st and/or 15th) each keep 1-9999 copies. Options cover suspended accounts, access logs, bandwidth data, local or cluster DNS, and system files. MySQL can be dumped per account, as the whole data directory, or both. PostgreSQL is off unless enabled. A cPanel community thread (not official docs) says dated runs are written to /backup/YYYY-MM-DD/accounts/.
- Partial backups in cPanel (https://docs.cpanel.net/cpanel/files/backup-for-cpanel/): home directory, single database, per-domain forwarders and per-domain account-level filters, each downloaded as a .gz file. User-level filters are not in the filter download. A full backup cannot be restored from the user panel, only by root. An account near its quota can fail to back up because lock files cannot be written.
- Webmail filter model (https://api.docs.cpanel.net/openapi/cpanel/operation/store_filter/, API 11.138): numbered parameter groups (part, match, val, opt, action, dest; up to 4096 condition sets). Parts map to Exim variables: header from, subject, to, reply address, message body, message headers, any of to/cc, the List-Id header, the spam status, score and bar headers, 'not delivered', and error_message. String matches: is, matches, contains, does not contain, begins, does not begin, ends, does not end, does not match. Numeric matches: is above, is not above, is below, is not below. Actions: deliver, save (folder), fail, finish (stop), pipe. Discard is shown in the UI. 'and' binds tighter than 'or'. A filter on the account applies to every mailbox, while a filter keyed by an address applies only to that mailbox.
- Autoresponder API (https://api.docs.cpanel.net/openapi/cpanel/operation/add_auto_responder/): email, domain, from, subject, body, is_html (0/1), interval in hours (0 = always reply), start and stop as Unix timestamps with stop after start, and charset (default UTF-8). Body placeholders are %subject%, %from% and %email%. Mail scoring 5 or higher is never answered (https://docs.cpanel.net/webmail/manage-your-inbox-in-webmail/). Forwarder API add_forwarder takes fwdopt fwd, fail, blackhole, system or pipe, with fwdemail (comma list), failmsgs, fwdsystem and pipefwd. Spam threshold API add_spam_filter takes required_score, which must be above 0 and below the account owner's own threshold. The documented default of 5 is called aggressive. The webmail UI accepts 1-50 and recommends 15 or more.
- Mail client settings (https://docs.cpanel.net/cpanel/email/set-up-mail-client/): username is the full address. With TLS: IMAP 993, POP3 995, SMTP 465. Without: IMAP 143, POP3 110, SMTP 587. Host is mail.<domain> when it has a valid certificate, otherwise the server hostname. Auto-setup scripts exist for iOS/macOS and Windows Live Mail. LDAP is not supported. cPanel's webmail runs on port 2096 (https://docs.cpanel.net/webmail/the-webmail-interface/). xMail can pick its own port, but should keep a dedicated TLS listener and the webmail.<domain> alias.
- Feature Manager keys confirmed by the list_features API example: blockers (email filters), emailtrace (track delivery), boxtrapper. Display names (no keys shown) at https://docs.cpanel.net/whm/packages/feature-manager/ include Webmail, Autoresponders, Forwarder Manager, Email Domain Forwarding, Email Filtering Manager, Apache SpamAssassin, SpamAssassin Spam Box, BoxTrapper, Email Trace, Email Disk Usage, Calendars and Contacts, Mailing Lists, Two-Factor Authentication, Password & Security, Contact Information and Update Notification Preferences. Each xMail tool should map to one xPanel plan feature flag so hosts can disable it.
- aaPanel docs map: the website functions are on https://www.aapanel.com/docs/Function/php.html (PHP project) and https://www.aapanel.com/docs/Function/proxy.html (proxy project). /docs/Function/Website.html is only a primer on basic terms. Security tools (firewall, port/IP/forward/region rules, SSH, brute-force, compiler access, anti-intrusion, hardening) are on https://www.aapanel.com/docs/Function/Security.html. Panel security is on https://www.aapanel.com/docs/Function/Settings.html. The recycle bin is on https://www.aapanel.com/docs/Function/Files.html. Default paths are web root /www/wwwroot/, backups /www/backup/, and panel backup/restore in /www/backup/backup_restore/.
- aaPanel firewall semantics (https://www.aapanel.com/docs/Function/Security.html): the system firewall denies by default, while region rules default to allow and can only block. Port rule fields are protocol TCP/UDP/both, port 1-65535, listening status, allow/deny, inbound/outbound, any or specific source, and remark. IP rule actions are block or release. Port forwarding fields are TCP/UDP, source port, target IP (127.0.0.1 for local) and target port. Every rule type has import and export. The docs warn that geo-IP is inexact and say to release your own ranges before blocking a region. SSH root login options are yes, no, without-password and forced-commands-only, which map to the sshd PermitRootLogin values yes, no, prohibit-password and forced-commands-only.
- aaPanel recovery menu (https://www.aapanel.com/docs/faq/Panel_Related.html), which xPanel should copy as a root-only CLI such as 'xpanelctl': 1 restart, 2 stop, 3 start, 4 reload, 5 change password, 6 change username, 8 change port, 9 clear cache, 10 clear login limit, 11 toggle IP+User-Agent session check, 12 remove domain binding, 13 remove IP restriction, 14 show panel URL and login info, 16 repair, 22 error log, 23 turn off BasicAuth, 24 turn off 2FA, 27 toggle panel SSL, 28 change entrance, 33 lift brute-force lock. A wrong entrance returns 404 by default, and the response can be configured.
- aaPanel API (https://www.aapanel.com/docs/api/api-list.html): enabled under Settings > API with a required caller IP whitelist. Each request carries request_time (milliseconds) and request_token = md5(request_time + md5(secret)). Example calls are config?action=get_token and v2/data?action=getData&table=sites with p, limit, search, order and type. For xPanel, keep the same shape (timestamp, token, IP allow list, bounded clock skew) but sign with HMAC-SHA256 instead of nested MD5.
- aaPanel paid Professional modules, which stay out of scope (https://www.aapanel.com/docs/Function/Professional.html): Nginx WAF, Apache WAF, Website statistics v1/v2, Website Tamper-proof, Tamper-proof for Enterprise, PHP code security, Load balance, aaPanel user manager, Abnormal Push, System hardening, Disk analysis, Anti-intrusion, Task manager, Platform Ops, File monitor, NFS Manager, Files Sync, Website Analytics, aaPanel Mobile. Brute-force protection and compiler access appear on the free Security page and are not in the Pro table, so they are kept in scope.
- aaPanel recycle bin (https://www.aapanel.com/docs/Function/Files.html): the file bin is on by default and catches deleted site directories. The MySQL database bin is off by default, and when it is on, deleting a database only marks it. Each item shows name, original directory, size and removal time, with recover, delete permanently and empty. The docs give no retention period, so xPanel should add a configurable retention (for example 30 days) and include the bin in quota accounting.
- aaPanel docs leave many defaults unstated: traffic-limit fields, redirect keep-path, hotlink response code, reverse-proxy timeout, alert defaults and login lock thresholds. The values in the tool behaviors for these are xPanel design choices, not documented aaPanel behavior. The xMail read, compose, reply, attachment and search behaviors are also generic webmail design, because cPanel's docs only list these Roundcube capabilities without detail (https://docs.cpanel.net/webmail/webmail-clients/).

- WHM's SSL/TLS Configuration page has one setting, the server-wide default key type, and it maps to the existing default-key-type tool. The default is RSA 2048. Changing it triggers an AutoSSL run that reissues certificates with the new type, and a user-level choice overrides the server default. Source: https://docs.cpanel.net/whm/ssl-tls/ssl-tls-configuration/
- DNS cluster role semantics. Standalone accepts newer serials and never pushes. Synchronize syncs in both directions, newest change wins. Write-only pushes without checking zones and can overwrite newer data, so two write-only members must never feed the same peer. Default failure threshold: 10 failed commands, then the member is disabled and must be re-enabled by hand. Every member must use the same DNS backend when DNSSEC zones exist. Source: https://docs.cpanel.net/whm/clusters/dns-cluster/
- Configuration cluster. Only the master knows who the members are. Members are authenticated by an API token with full root privilege. Removing a member keeps the settings it already received. The master can overwrite local changes made on members. Source: https://docs.cpanel.net/whm/clusters/configuration-cluster/
- The WHM 'Scripts' section is a command-line reference: about 5 pages of roughly 20 server scripts each, covering backup, restore and metadata, AutoSSL checks, DNS cleanup, mailbox format conversion, MySQL limit tuning and more. These are CLI tools rather than UI pages, so they are not listed as tools. xWHM should still ship a CLI with equivalent subcommands for automation parity. Source: https://docs.cpanel.net/whm/scripts/
- A theme package uploaded to the theme manager must include the password-change pages. Without them, forced or policy-driven password changes break. Branding (Customization) accepts SVG logos for light and dark backgrounds, an .ico favicon, a menu color in hex, help and documentation link targets, and a public contact name and URL for placeholder pages. Sources: https://docs.cpanel.net/whm/themes/theme-manager/ , https://docs.cpanel.net/whm/cpanel/customization/
- Spam daemon startup defaults: allowed IPs 127.0.0.1 and ::1 (empty means any IP), max connections per child 200, children 1, TCP timeout 30 s (0 turns it off), child timeout 300 s. Mailbox conversion supports maildir and mdbox, with an option to keep the old files. The mail queue search matches begins-with, exact or partial on metadata only, never on message bodies. Sources: https://docs.cpanel.net/whm/email/spamd-startup-configuration/ , https://docs.cpanel.net/whm/email/mailbox-conversion/ , https://docs.cpanel.net/whm/email/mail-queue-manager/
- The user panel's statistics sidebar puts a resource into the warning state at 80% of its quota. Both the user panel and the admin panel use the '/' key to focus search. The admin search also finds accounts by username or primary domain and ranks exact matches first. Sources: https://docs.cpanel.net/cpanel/the-cpanel-interface/the-cpanel-interface/ , https://docs.cpanel.net/whm/the-whm-interface/the-whm-interface/

Deprecated upstream, not to be rebuilt: SYS Firewall (replaced by Security), PM2 Manager (replaced by Node.js Project), Docker Manager (replaced by the Docker menu), DNS Manager plugin, Anti-Spam Gateway, the legacy Website statistics, and Sync Tool.
